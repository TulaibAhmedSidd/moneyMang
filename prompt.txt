138. MOST IMPORTANT ARCHITECTURAL RULES
============================================================

1. ONE BACKEND.

2. ONE AUTHORITATIVE API.

3. MOBILE AND ADMIN USE THE SAME API.

4. ADMIN PANEL MUST NOT DIRECTLY ACCESS MONGODB.

5. MOBILE MUST NOT DIRECTLY ACCESS MONGODB.

6. BUSINESS LOGIC BELONGS IN BACKEND SERVICES.

7. DO NOT DUPLICATE BUSINESS LOGIC BETWEEN MOBILE AND ADMIN.

8. BACKEND IS THE SOURCE OF TRUTH.

9. EVERY USER-OWNED RESOURCE MUST BE USER-SCOPED.

10. NEVER TRUST USER ID FROM CLIENT REQUESTS.

11. ADMIN ACCESS MUST BE RBAC/PERMISSION BASED.

12. FRONTEND ADMIN PROTECTION IS NOT SECURITY.

13. EVERY ADMIN API MUST ENFORCE AUTHORIZATION SERVER-SIDE.

14. ADMIN FINANCIAL-DATA ACCESS MUST BE LIMITED AND AUDITED.

15. NORMAL USERS MUST NEVER ACCESS ADMIN APIs.

16. ADMINS MUST NOT AUTOMATICALLY HAVE UNRESTRICTED ACCESS TO PRIVATE FINANCIAL DATA.

17. NEVER STORE PLAINTEXT PASSWORDS.

18. NEVER EXPOSE SECRETS TO MOBILE OR BROWSER.

19. NEVER USE FLOATING-POINT MONEY CALCULATIONS CARELESSLY.

20. USE IDEMPOTENCY FOR FINANCIAL MUTATIONS WHERE APPROPRIATE.

21. USE PAGINATION FOR LARGE DATASETS.

22. USE MONGODB AGGREGATION FOR LARGE ANALYTICS.

23. DO NOT HARD-CODE CURRENCY.

24. DO NOT HARD-CODE TIMEZONE.

25. DO NOT HARD-CODE DATE FORMATS.

26. DESIGN FOR GLOBAL USERS.

27. START WITH A MODULAR MONOLITH.

28. DO NOT PREMATURELY INTRODUCE MICROSERVICES.

29. KEEP MOBILE UI AND ADMIN UI SEPARATE.

30. KEEP DOMAIN/BACKEND LOGIC SHARED.
